# Minecraft Party 0.8.0 — public and private lobbies

- New Parties are **private by default**. The visibility button beside Create Party explicitly selects Public or Private; this choice is not persisted for the next Party.
- Private Parties remain accessible by their six-digit code and never appear in the public directory, including rooms created by older mods.
- Public Parties appear in **Party → Public parties…**, with their name, host name, occupied slots, capacity and playing/lobby status. Join uses the existing code exchange, pinned TLS lobby and Minecraft authentication. No address, full invitation, owner capability, chat history or member UUID is included in the list.
- The native Minecraft screen provides pagination, Refresh, disabled joining of full rooms and automatic refresh every 15 seconds. Requests and parsing run on the Party worker, not the render thread; resizing/closing screens discards stale replies.
- The authenticated host renews the listing and its counts every 10 seconds. Normal leave/revocation removes the old entry. If the host disappears or cannot reach the directory, the entry expires within about two minutes of its last successful heartbeat. Counts can be briefly stale and are host-provided advertisements, not verified identities.
- Public/private visibility travels in the TLS state and is retained during leadership handoff. A successor publishes a fresh code under the new leader; the old registration is retired or expires. Worlds themselves are not migrated.
- Windows testing exposed a pre-existing TLS teardown stall while closing a world stream. The raw TCP transport is now retained separately and closed before JSSE cleanup, releasing blocked writers before TLS close waits for their lock. TLS 1.3, certificate pinning and Minecraft login checks remain in use.
- Bulk stream copies on Windows use platform daemon threads; Linux retains virtual threads. Each authenticated member can open only one world stream, bounding the number of copying threads. This targets the stalled simultaneous socket reads/writes exposed by the Windows loopback test.

**All participants need 0.8.0**: the lobby wire protocol is now MPT4. The Cloudflare Worker must also be deployed from current main. Its `/health` response includes `"publicLobbies":true`; public creation/listing fails explicitly if that service update is missing. The HTTPS service protocol remains v1 and older private rooms stay private. Existing default service URLs require no change.

Discovery is limited to this directory instance, currently up to 256 registered Parties, with pages of at most 16 entries and request limits. Visibility is chosen on creation; recreate a Party to change it. A public join code is intentionally discoverable by anyone. Private codes remain access credentials and should be shared privately.

Validation includes Java model/strict response-parser tests, bounded wire roundtrips, real loopback TLS leadership migration, Node registry authorization/expiry tests and Wrangler's actual SQLite Durable Object runtime. These are not two running Minecraft clients, a GUI test, or an internet/e4mc play session; those still require real clients.
